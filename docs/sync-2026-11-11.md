## 原生差異不是缺漏

- **保留 obw binding／明確回寫。** 上游退休的是依賴 cc-mobile launcher 的 terminal binding；目標使用宿主 session entries 與明確 `/obw-sync`，不存在相同依賴。沒有刪除 `/obw-bind`、`/obw-unbind` 或 `/obw-sync`。
- **保留 init／jot。** 上游合併為單一 pm 技能，不代表必須刪除目標既有入口。
- **工作提示優先序：** `pm.work_prompt` → `--obw-work-prompt` → 內建提示。每次按下重讀專案設定；更換 vault／project 必須重開視窗。未知 placeholder 保留。OMP 等待訊息 admission；Pi 使用其原生訊息提交介面。
- **評分位置經使用者核准：** `~/.local/share/omp-plugins/wrap-up/ratings.jsonl`，以 `host`＋原生 `session_id` 區分。取消不記分；評分失敗不授權其他操作。不讀寫 Claude 資料。
- **配額的背景成本：** 只在啟用的互動 widget 輪詢；隱藏、關閉及 headless 啟動不開背景輪詢。Pi 子程序移除 Pi 專屬 `PI_CODING_AGENT_DIR`，避免把 Pi 資料夾誤當 OMP 帳號來源。
- **Pi 支援範圍：** 本輪提供 obw／wrap-up／omp-quota 原生 extension 與 Fizzy 技能。既有含 OMP `ask`、`task`、`skill://` 等原語的技能，不因文字相近就宣稱已在 Pi 等價驗收；obw 的 Pi manifest 仍不載入 OMP 專用技能。

## 驗證與限制

- `wrap-up`：19 項測試通過；真實 OMP／Pi 各完成一次模型 → 原生選擇／評分 → Node 寫入 → 讀回。驗收評分只寫隔離 HOME，不是使用者評價，驗收後移除。
- `omp-quota`：修正生命週期、請求順序與 killed 結果後，最終 33 項測試通過，包含狀態區分、stale 年齡、欄對齊與 worsening 顯示；不固定整行空白或文案。真實兩宿主都顯示實際 provider／window 配額，`/quota refresh` 都回覆 `omp quota refreshed`，沒有模型回合。
- obw：相關核心行為測試通過；host-free 與 Pi 型別檢查通過；`bash obw/tests/run.sh` 14 組通過。原生 UI 與 pm 工具的真實驗收紀錄見下列套件收據。
- 首次驗收時 OMP 使用 standalone binary，沒有同版本 JS SDK。整理提交時經使用者授權，在 repo 外隔離安裝 OMP 18.18.6 SDK，透過 `OBW_OMP_ROOT` 與暫時的 `obw/node_modules/@oh-my-pi/pi-tui` 連結執行原有 hooks；完整 `obw check` 通過（型別檢查、兩宿主 loader、82 項測試與 14 組 shell 檢查）。同時修正新增程式的 lint、既有 readback 型別縮窄與過期版本 fixture，移除兩項只驗證 mock wiring／固定文案的測試；保留行為測試。暫存 SDK 與連結在提交後移除，未替換目前 OMP。
- Fizzy：本機 `v3.0.3` 可登入，但 `--help` 缺少來源要求的 `account`、`--profile`、`--json`；回應為 `success` 而非來源 `ok`。Pi 真實技能已按前置檢查拒絕繼續；OMP 的原生套件清單可辨識該套件，但 print-mode 技能驗收未取得完整回覆。未升級 CLI，未宣稱完整 Fizzy 流程通過。
- 未新增相容 shim，未移植 Claude Mod／hooks，未更動 cc-plugins；本次整理分功能建立本機提交，不推送遠端。

### obw 真實宿主收據

- 兩宿主使用 `obsidian` vault 的專用 `obw-dual-host-test` project；既有卡片僅讀取，另建一張本輪暫存驗收卡。
- 在 CLI 更改暫存卡標題後，兩個已開啟的 `/issue` 都自動顯示新標題與新的標題排序，沒有重開視窗或手動刷新。
- OMP 的 `native` 文字篩選與 low 優先級篩選只留下暫存卡；Pi 從 title 切到 priority 後，medium 舊卡移到 low 新卡前方。兩宿主均顯示 `[M]`／`[L]` 與 tags。
- 兩宿主從 `parent` 關係開啟既有卡，再以 Back 返回原卡；未執行 Bind 或寫回。
- 兩宿主按 `w` 後都在原會話收到專案設定要求的 `OBW_NATIVE_PROMPT_OK`，且卡片顯示 Sent to agent。OMP 回覆位於 custom pane 後方，退出 pane 後可讀取；未另啟會話或呼叫任務工具。
- 兩宿主按 `o` 各產生一份 viz HTML。實際瀏覽器頁面顯示該卡的 Description、Acceptance Criteria、Agent、Notes；不是只檢查 render.sh 的退出碼。
- Pi 模型在正式 extension 中依序呼叫三個 pm 工具，三筆均回傳 `ok:true` 與暫存卡路徑；經真 CLI 讀回，status 為 `in-progress`、第一項 AC 為 `[x]`、Notes 含指定驗收文字。
- 此次不重驗跨宿主 binding ownership、完整 A10 或所有既有回寫故障情境；不以新 UI／工具驗收覆蓋那些歷史限制。
